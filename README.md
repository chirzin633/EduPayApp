# EduPay

School payment management system. A Laravel REST API serves academic years, classes, students, fee components, invoices, payments, PDF receipts, and financial reports to a React admin panel for school administrators and principals.

## Key Features

- **Sanctum authentication** with login, logout, and current-user endpoints; tokens expire after 7 days, and login is limited to 5 attempts per minute.
- **Role-based access control** for `admin` and `principal` users; inactive accounts are rejected and their tokens are revoked.
- **Academic years and classes** with active/inactive status; only one academic year can be active at a time.
- **Students** with NIS, personal data, parent contact, active/inactive status, and soft deletes.
- **Per-year class assignments** with one assignment per student per academic year.
- **Fee components** with default amounts and soft deletes.
- **Invoices** with multiple fee items, percentage or fixed-amount discounts, automatic totals, and statuses `unpaid`, `partially_paid`, `paid`, and `cancelled`.
- **Invoice item snapshots** so later fee-component changes do not alter existing invoices.
- **Invoice cancellation** allowed only when no completed payment exists.
- **Payments** with full or partial amounts, methods `cash`, `bank_transfer`, `qris`, and `debit_edc`, automatic receipt numbers, and balance recalculation.
- **Payment voids** with a required reason, voiding user, timestamp, and automatic invoice recalculation.
- **PDF receipts** generated with DomPDF and cached; receipts are unavailable for voided payments.
- **Dashboard** with summary cards, monthly revenue, invoice status distribution, revenue by payment method, and top outstanding classes, filterable by academic year.
- **Financial reports** for payments, outstanding balances, and student history, with filters and CSV export.
- **CSV export hardening** that neutralizes spreadsheet formula injection in exported text values.
- **API documentation** generated by Scramble at `/docs/api`.
- **React admin panel** with protected routes, role-aware navigation, and light/dark theme.

## Installation & Setup

### Backend

1. Install PHP dependencies:

   ```bash
   cd server
   composer install
   ```

2. Create the environment file and application key:

   ```bash
   cp .env.example .env
   php artisan key:generate
   ```

3. Configure the database in `server/.env`. The default file uses SQLite; this application requires PostgreSQL because reports use PostgreSQL-specific SQL:

   ```env
   APP_URL=http://localhost:8000

   DB_CONNECTION=pgsql
   DB_HOST=127.0.0.1
   DB_PORT=5432
   DB_DATABASE=edupay
   DB_USERNAME=postgres
   DB_PASSWORD=your-password
   ```

4. Create the database, run migrations, and seed the default users:

   ```bash
   psql -U postgres -c "CREATE DATABASE edupay;"
   php artisan migrate --seed
   ```

   The seeder creates these development accounts:

   | Role      | Email             | Password |
   | --------- | ----------------- | -------- |
   | Admin     | `admin@mail.com`  | `admin`  |
   | Principal | `kepsek@mail.com` | `kepsek` |

   These are development credentials. Change both passwords before deploying.

5. Start the API:

   ```bash
   php artisan serve
   ```

   The API runs at `http://localhost:8000/api`. Generated API documentation is at `http://localhost:8000/docs/api`.

   There is no registration endpoint. Use a seeded account or create users directly in the database.

### Frontend

1. Install dependencies:

   ```bash
   cd client
   npm install
   ```

   The client expects Mazer static assets in `client/public/mazer`. That directory is gitignored, so copy the assets there before starting the development server.

2. Point the frontend at the API in `client/.env`:

   ```env
   VITE_API_BASE_URL=http://localhost:8000/api
   ```

3. Start the development server:

   ```bash
   npm run dev
   ```

   Open `http://localhost:5173`.

Run the backend and frontend in separate terminals. For a production build, run `npm run build` in `client`.
